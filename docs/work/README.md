## 한 건의 수명

```text
이슈(예상·예상 마감·완료 조건)  ->  브랜치  ->  PR(영역 하나)  ->  CI  ->  머지  ->  이슈에 실제 마감·어긋난 이유
```

알고 싶은 것마다 볼 곳이 하나씩 있다.

| 알고 싶은 것 | 볼 곳 |
|---|---|
| 지금 어디까지 왔는가 | ROADMAP |
| 무엇을 만들기로 했고 언제 끝날 것으로 봤는가 | 이슈 |
| 왜 그렇게 정했는가 | 이슈의 "판단이 필요한 곳", ORIGIN.md |
| 무엇을 바꿨는가 | PR |
| 실제로 무엇을 확인했는가 | VERIFICATION, experiments/의 README |
| 사용자에게 무엇이 나갔는가 | CHANGELOG |

## 없는 예상을 뒤늦게 만들어 넣지 않는다

나중에 채운 예상은 언제나 실제와 맞아서, 맞았다는 사실이 아무것도 말해 주지 않는다.

이 저장소의 첫 덩어리(변환기부터 평가 유효성 확인까지)는 2026-10-11과 10-12에 이슈도 예상도 없이 한 번에
만들어졌다. 그 사실을 ROADMAP에 그대로 적었고, 거기에 예상 시간을 지어 넣지 않았다. 예상과 실제를 비교할 수
있는 기록은 그 뒤의 이슈부터다.

## 완료 조건은 "무엇을 보면 끝인가"로 적는다

"지원한다", "개선한다"는 완료 조건이 아니다. 돌릴 명령과 볼 출력으로 적는다.

결론이 어느 쪽으로 나든 완료가 되게 적는다. 실험이 가설을 뒤집어도 그 근거가 문서에 남으면 그 이슈는 닫힌다.
완료 조건이 원하는 결과에 매여 있으면 이슈가 영영 열려 있거나 근거 없이 닫힌다.

## 중단 규칙은 재기 전에 적는다

측정으로 정하는 일은 어떤 수치가 나오면 그만두거나 결론을 바꿀지를 재기 전에 적는다. 규칙은 원하는 결론이
나오지 않을 때만 값을 한다.

## 결정에는 선택지와 포기한 것을 함께 적는다

선택지가 둘 이상이었던 결정은 이슈에 네 가지를 적는다. 어떤 선택지가 있었는가, 무엇을 기준으로 골랐는가,
무엇을 골랐는가, 그래서 무엇을 포기했는가. 누가 정했는지도 적는다.

이 저장소에는 글에 값이 없어서 Claude가 고른 기본값이 여럿 있다. 그런 값은 ORIGIN.md 2절에 모아 두고,
사람이 확정하기 전까지 "확정되지 않음"으로 둔다.

## 한 번 잰 값으로 결론 내지 않는다

실험 03에서 같은 절차를 두 번 돌려 상한 배속이 7.50과 8.50으로, 수위 판정이 적정과 과잉으로 갈렸다.
수치를 근거로 쓰려면 몇 번 돌렸는지를 함께 적고, 한 번뿐이었으면 한 번이라고 적는다.

## 사람과 AI 세션이 함께 쓴다

이 저장소의 코드는 대부분 AI 코딩 세션이 썼다. 그래서 사람의 판단이 어디에 있었는지가 기록에 보여야 한다.

- 범위와 방향의 결정은 ORIGIN.md 2절에 누가 정했는지와 함께 적는다.
- AI가 고른 값은 AI가 골랐다고 적는다. 사람이 확정하면 그때 옮긴다.
- 사람이 정해야 하는 것은 `type:decision` 이슈로 열어 둔다. AI 세션이 대신 닫지 않는다.
